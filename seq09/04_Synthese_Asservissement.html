01 — Introduction

Principes généraux de l'asservissement

Un système asservi est un système de commande en boucle fermée dont l'objectif est de faire suivre à une grandeur de sortie une grandeur de consigne, en dépit des perturbations et des incertitudes.

Consigne r(t) Erreur ε(t) Commande u(t) Sortie y(t) ───────► ⊕ ──────► Correcteur C(p) ──────► Procédé G(p) ──────► ↑─────────────────────────────────────────────────────────┘ Retour (H(p) ou 1)
🎯
Précision

Annuler ou réduire l'erreur en régime permanent entre consigne et sortie.

⚡
Rapidité

Atteindre le régime permanent le plus vite possible (temps de réponse).

🔄
Stabilité

Garantir que la sortie converge sans oscillations divergentes.

🛡️
Robustesse

Conserver les performances malgré les variations du procédé.

02 — Généralités

Fonction de transfert

En utilisant la transformée de Laplace, la fonction de transfert d'un système linéaire invariant (LTI) est définie par :

Définition H(p) = Y(p) / E(p)
Y(p) : sortie | E(p) : entrée | p : variable complexe de Laplace

Forme générale

H(p) = K · [ b_m·p^m + ... + b_1·p + b_0 ] / [ a_n·p^n + ... + a_1·p + a_0 ]
n ≥ m pour un système causal (physiquement réalisable)
  • KGain statique du système (valeur à p = 0)
  • nOrdre du système = degré du dénominateur
  • PôlesRacines du dénominateur → déterminent la stabilité
  • ZérosRacines du numérateur → influencent la réponse
  • ClasseNombre d'intégrateurs en boucle ouverte (puissance de p au dénominateur)
ℹ️

Classe : un système de classe α contient un facteur pα au dénominateur, ce qui détermine les erreurs en régime permanent (voir §5).

03 — Premier ordre

Systèmes du 1er ordre

Modèle canonique d'un système du premier ordre :

H(p) = K / (1 + τ·p)
K : gain statique | τ : constante de temps (s)

Réponse indicielle (entrée échelon de valeur E)

La sortie en régime temporel est :

y(t) = K·E · (1 − e^(−t/τ))·u(t)
u(t) : échelon unité (Heaviside)

Caractéristiques temporelles

t = τ

y(τ) = 63,2 % de la valeur finale

t = 3τ

y(3τ) = 95 % — début de régime établi

t = 5τ

y(5τ) ≈ 99,3 % — régime permanent atteint

Tangente

La tangente à l'origine coupe la valeur finale en t = τ

Réponse fréquentielle

H(jω) = K / (1 + jωτ)
|H(jω)| = K / √(1 + ω²τ²)
∠H(jω) = −arctan(ωτ)
Fréquence de coupure : ω_c = 1/τ → |H| = K/√2 (−3 dB)

Réponse indicielle normalisée (K=1, τ=1 s)

04 — Deuxième ordre

Systèmes du 2e ordre

Forme canonique :

H(p) = K·ω_n² / (p² + 2ξω_n·p + ω_n²)
ω_n : pulsation propre (rad/s) | ξ : coefficient d'amortissement (sans dimension)
  • ω_nPulsation propre non amortie — détermine la rapidité
  • ξCoefficient d'amortissement — détermine le dépassement
  • ω_pPulsation propre amortie : ω_p = ω_n·√(1−ξ²) (si ξ < 1)

Régimes selon ξ

Condition Régime Pôles Comportement
0 < ξ < 1 Sous-amorti Complexes conjugués Oscillations amorties, dépassement
ξ = 1 Critiquement amorti Réel double −ω_n Retour le plus rapide sans oscillation
ξ > 1 Sur-amorti Réels distincts négatifs Pas d'oscillation, retour lent
ξ = 0 Non amorti Imaginaires purs ±jω_n Oscillations permanentes

Formules clés (régime sous-amorti, 0 < ξ < 1)

Dépassement : D% = exp(−πξ / √(1−ξ²)) × 100
Ex : ξ = 0.5 → D% ≈ 16.3% | ξ = 0.707 → D% ≈ 4.3%
Temps de pic : t_p = π / ω_p = π / (ω_n·√(1−ξ²))
Temps de réponse à 5% : t_r5 ≈ 3 / (ξ·ω_n)
Approximation valable pour 0.3 < ξ < 0.8

Réponse indicielle pour ξ = 0.3 / 0.7 / 1.0 (ω_n = 1, K = 1)

05 — Boucle fermée

Boucle fermée & erreurs en régime permanent

Transmittance en boucle fermée

Pour un retour unitaire H = 1 et un correcteur C(p) en série avec le procédé G(p) :

F(p) = C(p)·G(p) / (1 + C(p)·G(p))
F(p) : FTBF | C(p)·G(p) : FTBO (boucle ouverte)

Erreur de position (entrée échelon)

ε_p = lim[p→0] p·E(p) / (1 + FTBO(p)) = 1 / (1 + K_p)
K_p = lim[p→0] FTBO(p) — gain de position

Erreur de vitesse (entrée rampe)

ε_v = 1 / K_v où K_v = lim[p→0] p·FTBO(p)
Nulle si la FTBO contient au moins un intégrateur (classe ≥ 1)

Erreur d'accélération (entrée parabolique)

ε_a = 1 / K_a où K_a = lim[p→0] p²·FTBO(p)
Nulle si classe ≥ 2
ClasseÉchelonRampeParabolique
0finie (≠0)∞∞
10finie (≠0)∞
200finie (≠0)
💡

Pour annuler l'erreur de position, il suffit qu'il y ait au moins un intégrateur (1/p) dans la boucle ouverte (correcteur ou procédé).

06 — Stabilité

Stabilité des systèmes asservis

Un système LTI est stable si et seulement si tous ses pôles ont une partie réelle strictement négative (plan gauche du plan complexe).

Critère de Routh-Hurwitz

Permet de vérifier la stabilité sans calculer les pôles. Pour un polynôme caractéristique a_n·p^n + … + a_0, on construit le tableau de Routh. Condition nécessaire : tous les coefficients doivent être de même signe et non nuls.

⚠️

Si un élément de la 1re colonne du tableau de Routh change de signe, le nombre de changements de signe = nombre de pôles à partie réelle positive → système instable.

Marges de stabilité (domaine fréquentiel)

Marge de gain M_G

M_G = −|FTBO(jω_φ)|_dB, où ω_φ est la pulsation de déphasage −180°. Valeur typique : M_G ≥ 6 dB.

Marge de phase M_φ

M_φ = 180° + ∠FTBO(jω_c), où ω_c est la pulsation de coupure (|FTBO| = 0 dB). Valeur typique : M_φ ≥ 45°.

Critère de Nyquist

Tracé du lieu de Nyquist de la FTBO dans le plan complexe. Le système en boucle fermée est stable si le point critique (−1, j0) n'est pas encerclé (règle simplifiée pour systèmes stables en BO).

08 — Correcteurs

Correcteurs classiques

Correcteur Proportionnel (P)

C(p) = K_p

Simple et rapide, augmente le gain → réduit l'erreur statique mais peut déstabiliser.

Correcteur Intégral (I)

C(p) = K_i / p

Annule l'erreur statique pour une entrée échelon (classe +1). Ralentit le système et peut créer de l'instabilité.

Correcteur Dérivé (D)

C(p) = K_d · p

Anticipe les variations → améliore la marge de phase. Amplifie le bruit hautes fréquences — utilisé filtré.

Correcteur PID

C(p) = K_p · (1 + 1/(T_i·p) + T_d·p)
T_i : temps d'intégration | T_d : temps de dérivation
Action P

Réduit l'erreur, accélère la réponse. Risque d'oscillations si trop élevé.

Action I

Élimine l'erreur statique. Ralentit et peut déstabiliser (phénomène windup).

Action D

Améliore la marge de phase, amortit les oscillations. Sensible au bruit.

Correcteur à avance de phase

C(p) = K · (1 + aτp) / (1 + τp) avec a > 1
Augmente la marge de phase — améliore la rapidité

Correcteur à retard de phase

C(p) = K · (1 + bτp) / (1 + τp) avec b < 1
Réduit le gain haute fréquence — améliore la précision

Méthode de réglage de Ziegler-Nichols

TypeK_pT_iT_d
PT/(K·L)——
PI0.9·T/(K·L)3.3·L—
PID1.2·T/(K·L)2·L0.5·L

K : gain, T : constante de temps, L : retard pur du procédé identifié par réponse indicielle.

09 — Temps de réponse

Temps de réponse à 5%

Le temps de réponse à 5% (noté tr5%) est le temps à partir duquel la sortie reste définitivement dans la bande ±5 % autour de la valeur finale. C'est le critère de rapidité le plus couramment utilisé en automatique.

|y(t) − y_∞| ≤ 0.05 · y_∞ pour tout t ≥ t_r5%
y_∞ : valeur finale en régime permanent
1er ordre

t_r5% = 3τ (la sortie atteint 95% de y_∞ en 3 constantes de temps)

2e ordre (sous-amorti)

t_r5% ≈ 3 / (ξ·ω_n) — formule approchée pour 0.3 < ξ < 0.8

Sur-amorti / critique

Plus lent que le cas critique. t_r5% se détermine graphiquement ou numériquement.

⚠️

Pour le système sous-amorti (ξ petit), la sortie peut osciller et rentrer puis sortir plusieurs fois de la bande à 5% : le tr5% est le dernier instant de sortie de bande, pas le premier passage.

💡

Un amortissement ξ ≈ 0.7 (dit « optimal ») offre le meilleur compromis entre rapidité et dépassement : tr5% minimal sans oscillations excessives.

Compromis fondamental : stabilité ↔ rapidité ↔ précision sont trois objectifs souvent antagonistes. Le rôle du correcteur est de les optimiser simultanément selon le cahier des charges.

11 — Exemples de code

Régulation d'un balancier inversé — C++ & Python

Le balancier inversé (pendule sur chariot, robot bipède, segway…) est le cas-école de l'asservissement instable : sans correcteur, le pendule tombe. On utilise un correcteur PID sur l'angle θ pour maintenir l'équilibre. Les deux implémentations ci-dessous partagent la même logique PID ; seul le langage diffère.

🔧

Modèle simplifié : l'angle θ est mesuré par un capteur (IMU / encodeur). La commande u (tension moteur ou couple) est calculée chaque pas d'échantillonnage dt. Le setpoint est θ = 0 (vertical).

1// ═══════════════════════════════════════════════════════════════
2// Régulateur PID — Balancier inversé          (C++17, embarqué)
3// Capteur : IMU (angle en radians)  |  Actionneur : moteur DC
4// ═══════════════════════════════════════════════════════════════
5
6#include <cmath>
7#include <algorithm>    // std::clamp
8#include <chrono>
9
10// ── ① Paramètres PID ─────────────────────────────────────────
11// ↓ RÉGLER CES TROIS VALEURS EN PREMIER
12constexpr double Kp = 45.0;   // Gain proportionnel  → rapidité de réaction
13constexpr double Ki =  2.5;   // Gain intégral       → supprime l'erreur statique
14constexpr double Kd =  8.0;   // Gain dérivé         → amortit les oscillations
15
16// ── ② Paramètres système ─────────────────────────────────────
17constexpr double DT         = 0.01;   // Pas d'échantillonnage (s) — doit être régulier
18constexpr double SETPOINT   = 0.0;   // Angle cible (rad) — 0 = vertical parfait
19constexpr double U_MAX      = 12.0;  // Saturation commande (V ou PWM normalisé)
20constexpr double ANGLE_FALL = 0.5;   // Seuil de chute (rad ≈ 28°) — coupe les moteurs
21
22// ── ③ Anti-windup : limite d'accumulation intégrale ──────────
23constexpr double INTEGRAL_MAX = 5.0;  // Clamp integral (évite la saturation prolongée)
24
25// ────────────────────────────────────────────────────────────
26class PIDController {
27public:
28    PIDController(double kp, double ki, double kd)
29        : kp_(kp), ki_(ki), kd_(kd), integral_(0), prev_error_(0) {}
30
31    // Calcule la commande u à chaque pas dt
32    double compute(double setpoint, double measured, double dt) {
33        double error     = setpoint - measured;
34
35        // Terme Proportionnel
36        double P = kp_ * error;
37
38        // Terme Intégral + anti-windup (clamping)
39        integral_ += error * dt;
40        integral_ = std::clamp(integral_, -INTEGRAL_MAX, INTEGRAL_MAX);
40        double I = ki_ * integral_;
41
42        // Terme Dérivé (différences finies arrière)
43        double D = kd_ * (error - prev_error_) / dt;
44        prev_error_ = error;
45
46        // Commande totale saturée
47        return std::clamp(P + I + D, -U_MAX, U_MAX);
48    }
49
50    void reset() { integral_ = 0; prev_error_ = 0; }
51
52private:
53    double kp_, ki_, kd_;
54    double integral_, prev_error_;
55};
56
57// ── Boucle principale (appelée par le scheduler temps-réel) ──
58int main() {
59    PIDController pid(Kp, Ki, Kd);
60
61    // Remplacer cette boucle par l'ISR ou le timer de votre MCU
62    while (true) {
63        double theta = readIMU();          // ④ lecture capteur (rad)
64
65        // ── ⑤ Sécurité : arrêt si chute détectée ────────────
66        if (std::abs(theta) > ANGLE_FALL) {
67            setMotor(0.0);
68            pid.reset();
69            continue;
70        }
71
72        double u = pid.compute(SETPOINT, theta, DT);
73        setMotor(u);                       // ⑥ envoi commande
74
75        sleepMs(DT * 1000);               // ⑦ attendre prochain pas
76    }
77}

Guide des paramètres C++

① Kp — Gain proportionnel

Réaction immédiate à l'écart angulaire. Augmenter Kp accélère la correction mais provoque des oscillations. Diminuer si le robot tremble. Point de départ typique : 30–60 selon la masse.

① Ki — Gain intégral

Compense la dérive lente (centre de gravité légèrement décalé). Ki trop élevé → instabilité par windup. Commencer à 0, augmenter par pas de 0.5 jusqu'à correction de la dérive.

① Kd — Gain dérivé

Amortit les oscillations rapides. Kd trop élevé → amplification du bruit capteur → vibrations haute fréquence. Augmenter progressivement jusqu'à disparition des oscillations.

② DT — Pas d'échantillonnage

Doit être constant et régulier (timer matériel recommandé). Un DT trop grand (>50 ms) dégrade le terme dérivé. Valeur typique : 5–20 ms pour un pendule physique.

② U_MAX — Saturation

Limite la commande à la plage physique du moteur. Réduire si le robot fait des à-coups mécaniques. Trop faible → système incapable de rattraper une grande perturbation.

③ INTEGRAL_MAX — Anti-windup

Empêche l'intégrale d'accumuler indéfiniment lors d'une saturation prolongée. Sans ce clamping, le système met du temps à réagir après une perturbation forte.

⑤ ANGLE_FALL — Sécurité

Seuil angulaire au-delà duquel le système considère que le robot a chuté. Coupe les moteurs et remet l'intégrale à zéro. Typiquement 25–35° (0.45–0.6 rad).

④⑥ readIMU / setMotor

Fonctions à implémenter selon votre matériel (I²C pour MPU-6050, PWM pour L298N…). L'angle doit être filtré (filtre complémentaire ou Kalman) avant d'entrer dans le PID.

5
6import numpy as np

13Kd =  8.0   # Gain dérivé         → amortit les oscillations

17T_SIM        = 10.0    # Durée totale simulation (s)
18SETPOINT     = 0.0     # Angle cible (rad) — 0 = vertical
19U_MAX        = 12.0    # Saturation commande (N ou V)
20INTEGRAL_MAX = 5.0     # Anti-windup : borne intégrale
21

23g   = 9.81    # Accélération gravitationnelle (m/s²)
24L   = 0.30    # Longueur du pendule (m) — adapter à votre robot
25m   = 0.50    # Masse du pendule (kg)
26M   = 1.50    # Masse du chariot (kg)
27b   = 0.05    # Frottement visqueux (N·s/m) — friction moteur+roues

29# ────────────────────────────────────────────────────────────
30class PIDController:
31    def __init__(self, kp, ki, kd):
32        self.kp, self.ki, self.kd = kp, ki, kd
33        self.integral   = 0.0
34        self.prev_error = 0.0
35
36    def compute(self, setpoint, measured, dt):
37        error = setpoint - measured
38
39        # Terme Proportionnel
40        P = self.kp * error
41
42        # Terme Intégral + anti-windup
43        self.integral += error * dt
44        self.integral  = np.clip(self.integral, -INTEGRAL_MAX, INTEGRAL_MAX)
45        I = self.ki * self.integral
46
46        # Terme Dérivé
47        D = self.kd * (error - self.prev_error) / dt
48        self.prev_error = error
49
50        return np.clip(P + I + D, -U_MAX, U_MAX)
51

54    """Équations du mouvement du pendule inversé (linéarisées autour de θ=0)."""
55    # ④ Modifier L, m, M, b pour correspondre à votre physique réelle
56    denom = (M + m)
57    # Accélération angulaire (approximation sin(θ)≈θ pour petits angles)
58    theta_ddot = (g / L) * theta - (u / (m * L)) - (b / (m * L**2)) * theta_dot
59    return theta_ddot

Guide des paramètres Python

① Kp, Ki, Kd

Mêmes effets qu'en C++. En simulation, commencer par Ki = 0, Kd = 0, régler Kp jusqu'à oscillation, puis ajouter Kd pour amortir, enfin Ki pour corriger la dérive.

③ L — longueur du pendule

Paramètre physique critique. Un pendule plus long (L↑) est plus lent à tomber → les gains peuvent être plus faibles. L court → réponse très rapide nécessaire → gains élevés.

③ m, M — masses

Le ratio m/M influence le couplage entre chariot et pendule. Augmenter M (chariot lourd) améliore la stabilité mais nécessite plus de couple moteur. Adapter U_MAX en conséquence.

③ b — frottement

Coefficient de frottement visqueux. Un b élevé agit comme un amortisseur naturel et réduit le besoin de Kd. En pratique, identifier b expérimentalement (réponse libre à l'impulsion).

② DT — pas de simulation

Doit être suffisamment petit pour la stabilité numérique : DT < 1/(10·ω_n). Pour un pendule avec ω_n ≈ √(g/L) ≈ 5.7 rad/s → DT < 0.017 s. Utiliser RK4 si DT > 10 ms.

⑤ theta initial

Angle de perturbation initiale. Tester avec 0.05 rad (petite), 0.15 rad (moyenne), 0.3 rad (grande). Si le système diverge au-delà de 0.1 rad, les gains sont insuffisants.

② INTEGRAL_MAX

Si le système oscille lentement en régime établi → Ki trop grand ou INTEGRAL_MAX trop élevé. Réduire l'un des deux. Si dérive résiduelle → INTEGRAL_MAX trop petit.
